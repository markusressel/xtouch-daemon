Home Assistant¶

A homeassistant channel is a strip that belongs to Home Assistant instead of PipeWire: every part of it is an entity there, and automations decide what it does. For example, the fader dims a light, the encoder sets the volume of a speaker in another room, a button toggles a scene. The daemon reaches Home Assistant over MQTT discovery, so it needs the [mqtt] section.

PipeWire or Home Assistant?¶

Each control has one owner. The audio channels (output, input, apps) and the pools (auto, apps, ...) control audio on this computer and need nothing else. A homeassistant channel controls nothing by itself; it only reports what happens on it and shows what Home Assistant sets. In between, an audio channel can hand its fader or its encoder to Home Assistant and keep the other one for the volume, see below, and [controls] hands a control of a slot to Home Assistant whatever the slot shows. Never both on one control: a fader that both set a PipeWire volume and were moved by Home Assistant would fight over the motor.

[mqtt]¶

The MQTT broker of Home Assistant, e.g. the Mosquitto add-on. Anything that is an entity in Home Assistant needs it (homeassistant channels and controls, homeassistant = true on a state); without such, the section is optional, and with it the daemon still shows the device, its modes, states and slots in Home Assistant.

Option Default Meaning
host required The broker, e.g. "homeassistant.local".
port 1883 Its port.
username none The user to log in as.
password none The password, in the file.
password_file none A file that holds the password instead, e.g. one only you can read. ~ is the home directory. Surrounding whitespace is ignored.
password_env none An environment variable that holds the password instead, e.g. set with systemctl --user edit xtouch-daemon (Environment=).
discovery_prefix "homeassistant" Home Assistant's MQTT discovery prefix.
namespace "xtouch" Starts every entity ID (number.xtouch_lamp_fader) and is part of the topics. Lower case letters, digits, _.
device_name "X-Touch Extender" The name of the device in Home Assistant.

Set at most one of password, password_file and password_env. A password file that can't be read, or a variable that is not set, stops the daemon at the start with a message.

[mqtt]
host = "homeassistant.local"
username = "xtouch"
password_file = "~/.config/xtouch-daemon/mqtt-password"

A changed [mqtt] section needs a restart of the daemon (systemctl --user restart xtouch-daemon). Until then, a reload keeps the whole current configuration.

The entities are available in Home Assistant while the daemon runs and the device is connected; otherwise they are greyed out. A last will covers a crash. The daemon connects to the broker again by itself when it was gone.

The GUI shows whether the daemon is connected, and why not (e.g. a wrong password), and its "Test connection" button tries settings before they are saved.

homeassistant channels¶

Option Default Meaning
type required "homeassistant".
label none The top line of the LCD until Home Assistant sets one, and the start of the entity names (the id without it).
color "white" The LCD color until Home Assistant sets one. 
[mqtt]
host = "homeassistant.local"
username = "xtouch"
password_env = "XTOUCH_MQTT_PASSWORD"

[channel.living_room]
type = "homeassistant"   # number.xtouch_living_room_fader, ...
label = "Living"
color = "yellow"

[slots]
8 = "living_room"

The entities belong to the channel, not to a slot: they stay in Home Assistant whichever slot shows the channel, and while none does.

Audio strips with Home Assistant controls¶

An output, input or apps channel with encoder = "homeassistant" or fader = "homeassistant" keeps the volume on the other control and gets these entities of the list below:

Option Entities
encoder = "homeassistant" number.<ns>_<id>_encoder, and event.<ns>_<id>_buttons with encoder_pressed, encoder_released.
fader = "homeassistant" number.<ns>_<id>_fader, and event.<ns>_<id>_buttons with fader_touched, fader_released.
select = { press = "homeassistant" } (also rec, solo) event.<ns>_<id>_buttons with select_pressed, select_released.

The LCD and the LEDs stay with PipeWire, and so do the buttons unless they say homeassistant (see Buttons). The channel's id names the entities, its label starts their names. See Encoders for the details.

[channel.desk]
type = "output"
device = "alsa_output.usb-*"
label = "Desk"
encoder = "homeassistant"    # the fader sets the volume, the encoder dims the desk lamp

Controls of a slot¶

A control of a slot can belong to Home Assistant whatever the slot shows, with [controls]: the fader, the encoder (turn and push), and the Select, Rec and Solo buttons (an event per press, and a select for the LED). The entities are named by the slot (number.xtouch_slot_6_fader), or by id:

[controls]
6 = { fader = "homeassistant", id = "desk" }      # number.xtouch_desk_fader
4 = { encoder = "homeassistant" }                 # number.xtouch_slot_4_encoder

With the fader taken, the encoder sets the volume of what the slot shows; with only the encoder taken, the fader keeps it.

Entities¶

<ns> is mqtt.namespace, <id> the id of the channel (desk for [channel.desk]), or for a control of a slot its id or slot_<n>:

Entity What it is
number.<ns>_<id>_fader The fader, 0..100 in steps of 0.1. Setting it moves the motor fader; moving the fader by hand sets it (at most every 100 ms while it moves, and where it was let go).
number.<ns>_<id>_encoder The encoder, 0..100. The ring shows it; turning the encoder changes it by behavior.encoder_step per step.
number.<ns>_<id>_meter The LED meter, 0..100 %: 0 is dark, 100 lights it fully; the daemon holds the level (the device would let it fall). Its 14 levels are about 7 % each, 100 % lights the red LED at the top too, so e.g. a CPU load or a power ratio goes in as it is.
text.<ns>_<id>_top, text.<ns>_<id>_bottom The two lines of the LCD, 7 characters each.
select.<ns>_<id>_color The LCD color: off, red, green, yellow, blue, magenta, cyan, white.
select.<ns>_<id>_rec_led, _solo_led, _mute_led, _select_led The LEDs of the buttons: off, on or flash.
event.<ns>_<id>_buttons What happens on the strip: rec_pressed, rec_released, solo_…, mute_…, select_…, encoder_pressed, encoder_released, fader_touched, fader_released.

A button does not switch its LED: if a button should toggle something, an automation reacts to the event and sets the LED to show the result. Home Assistant keeps what it set last (retained on the broker), so after a restart of the daemon the strips show it again. New entities start with the configured label and color, the fader and encoder at 0 and the LEDs off. While the broker can't be reached, a strip shows its label, offline and its color, and the device does nothing on it.

Entities of a channel that was removed from the configuration are removed from Home Assistant on the next reload.

Choices¶

With [mqtt], an output or input channel with choices has select.<ns>_<id>_output (select.<ns>_<id>_input): the choice the strip shows, one option per choice, named by its label (or its device; a second choice of the same name gets a number, e.g. Out 2). Choosing one switches to it like Select on the device, profile first; one that isn't there is refused and the select goes back. The select follows the strip, also when the default changes elsewhere.

action: select.select_option
target:
  entity_id: select.xtouch_out_output
data:
  option: Speaker

Modes, states and slots¶

With [mqtt], Home Assistant sees and sets the states and modes:

Entity What it is
select.<ns>_mode The mode picked by hand, or auto for the rules. Choosing one picks it, like xtouch-daemon mode.
binary_sensor.<ns>_state_<id> Each state and mode, with the attributes since, source and override.
select.<ns>_state_<id> The override of each state that is no mode: auto, on, off.
switch.<ns>_state_<id>_input For states with homeassistant = true: what Home Assistant feeds into them.
binary_sensor.<ns>_<id>_shown Whether a channel is on a slot.
sensor.<ns>_slot_<n> What slot n shows (a channel id, app:<name>, person:<name> or none), with label, kind, via and reason.

For example, the mode gaming while the PC runs a game, from another room's automation:

action: select.select_option
target:
  entity_id: select.xtouch_mode
data:
  option: gaming

Automations¶

An automation that dims a light with the fader, shows its brightness on the LCD, and toggles it with Mute:

automation:
  - alias: "X-Touch: fader dims the living room"
    mode: queued
    triggers:
      - trigger: state
        entity_id: number.xtouch_living_room_fader
    actions:
      - action: light.turn_on
        target: { entity_id: light.living_room }
        data:
          brightness_pct: "{{ trigger.to_state.state | float | round(0) }}"
      - action: text.set_value
        target: { entity_id: text.xtouch_living_room_bottom }
        data:
          value: "{{ trigger.to_state.state | float | round(0) }}%"

  - alias: "X-Touch: Mute toggles the living room"
    triggers:
      - trigger: state
        entity_id: event.xtouch_living_room_buttons
        attribute: event_type
        to: mute_pressed
    actions:
      - action: light.toggle
        target: { entity_id: light.living_room }

  - alias: "X-Touch: the Mute LED shows the living room light"
    triggers:
      - trigger: state
        entity_id: light.living_room
    actions:
      - action: select.select_option
        target: { entity_id: select.xtouch_living_room_mute_led }
        data:
          option: "{{ 'on' if is_state('light.living_room', 'on') else 'off' }}"

  - alias: "X-Touch: the meter shows the power of the washing machine"
    triggers:
      - trigger: state
        entity_id: sensor.washing_machine_power
    actions:
      - action: number.set_value
        target: { entity_id: number.xtouch_living_room_meter }
        data:
          # 2000 W lights it fully
          value: "{{ [trigger.to_state.state | float(0) / 2000 * 100, 100] | min | round(0) }}"

To react to the entities from code, see As a haad controller.
