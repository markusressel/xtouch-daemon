Configuration¶

xtouch-daemon reads a TOML file, by default ~/.config/xtouch-daemon/config.toml ($XDG_CONFIG_HOME is respected). -c FILE selects another one. Without a file at the default path it uses the example configuration: six auto strips, the default input and the default output.

xtouch-daemon init-config      # writes the example to the default path (-f overwrites)
xtouch-daemon check-config     # validates the file and lists what each strip does

Unknown options are errors, so a typo does not go unnoticed. check-config names the place of every error, e.g. strip[3].label: String should have at most 7 characters.

The GUI edits the same options in a window and shows the same errors next to them.

Sections¶

Section What it configures Page
[device] Which sound card is the extender. Behavior
[behavior] Volume limit, encoder step, reset volume, meters, auto strips, collapsing strips. Behavior
[aliases] Names to show for applications on auto strips. Behavior
[[strip]] Up to eight strips, from the left (more with collapse). Strips
[mqtt] The MQTT broker of Home Assistant. Home Assistant

The strip types:

type What the strip controls Page
output, input An output or an input device, several of them, choices to switch between, or the default one. Devices
apps All streams of a group of applications. Applications
auto The next application that plays and has no strip of its own. Applications
homeassistant Nothing by itself: its parts are entities in Home Assistant. Home Assistant
empty Nothing. A dark strip. Strips

Applying changes¶

xtouch-daemon check-config && systemctl --user reload xtouch-daemon

A reload (SIGHUP) builds the strips from the new file without a restart. A file with errors is reported in the log and the current configuration stays.

Two sections need a restart (systemctl --user restart xtouch-daemon):

  • A changed [device] name. A reload takes the rest of the file, but keeps the old device.
  • A changed [mqtt] section. Until the restart, a reload keeps the whole current configuration.

The GUI applies a saved file the same way: it reloads the running daemon (the service, or one started from a terminal or an IDE), or offers a restart. It then tells whether the daemon took the file.

Complete example¶

[behavior]
max_volume = 130
encoder_step = 2
auto_hold = 10
ignore = ["speech-dispatcher", "notification"]

[aliases]
"WEBRTC VoiceEngine" = "Discord"

[[strip]]
type = "output"
device = "alsa_output.pci-0000_11_00.4.analog-stereo"
label = "Speaker"
color = "cyan"

[[strip]]
type = "output"
device = "bluez_output.4C_D7_3A_EA_02_76.1"
label = "Buds"
color = "green"

[[strip]]
type = "input"
label = "Mic"
color = "red"

[[strip]]
type = "apps"
match = ["@browsers"]
label = "Browser"
color = "yellow"

[[strip]]
type = "apps"
match = ["@games"]
label = "Games"
color = "magenta"

[[strip]]
type = "empty"

# strips 7 and 8 are not configured: they are "auto" strips
