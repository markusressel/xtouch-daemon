Configuration¶

xtouch-daemon reads a TOML file, by default ~/.config/xtouch-daemon/config.toml ($XDG_CONFIG_HOME is respected). -c FILE selects another one. Without a file at the default path the daemon uses the example configuration: the default input on slot 7, the default output on slot 8 and auto on the other six. The GUI starts with an empty file instead and writes it at the first save.

xtouch-daemon init-config      # writes the example to the default path (-f overwrites)
xtouch-daemon check-config     # validates the file and shows what each slot shows when

Unknown options are errors, so a typo does not go unnoticed. check-config names the place of every error, e.g. channel.mic.label: String should have at most 7 characters.

The GUI edits the same options in a window and shows the same errors next to them.

Editors and AI assistants¶

The options are also published as a JSON Schema, config.schema.json. A TOML language server, e.g. Taplo (Even Better TOML in VS Code) or Tombi, reads it: it completes the options, shows their help on hover and marks a wrong option while you type. The first line of the example configuration points to the schema of the latest release; add it to a file that has none:

#:schema https://markusressel.github.io/xtouch-daemon/latest/config.schema.json

For the schema of the installed version, write it next to the file and point to that instead:

xtouch-daemon schema > ~/.config/xtouch-daemon/config.schema.json

#:schema ./config.schema.json

An AI assistant that edits the file finds the options and their help there too. The schema checks each option on its own; check-config checks the rest, e.g. that a slot names a channel that exists, or that an option fits the type of the channel.

Sections¶

Section What it configures Page
[channel.<id>] What a strip can control: a device, a group of applications, a person, Home Assistant. Channels
[slots] What each strip of the device (a slot) shows, and when. Channels, states and slots
[state.<id>] States and modes (in a call, gaming) that the slots ask about. Channels, states and slots
[controls] Actions of the buttons, fader or encoder of a slot, whatever it shows. Channels, states and slots
[pool.apps], [pool.auto] How apps and auto take the next application that plays. Applications
[pool.people], [voip] The people of the voice chat, and where they sit. People
[pool.devices] Outputs and inputs without a channel (a USB headset) on the slots that name devices. Devices
[pool.<id>] A pool of your own: the next present channel of a list. Pools of channels
[device] Which sound card is the extender. Behavior
[behavior] Volume limit, encoder step, reset volume, meters. Behavior
[aliases] Names to show for applications on auto slots. Behavior
[switching] The chord and the banner of a new mode. Channels, states and slots
[mqtt] The MQTT broker of Home Assistant. Home Assistant

The channel types:

type What the channel controls Page
output, input An output or an input device, several of them, choices to switch between, or the default one. Devices
apps All streams of a group of applications. Applications
person Someone of the voice chat. People
homeassistant Nothing by itself: its parts are entities in Home Assistant. Home Assistant

In a slot, apps is the next application that plays and has no channel of its own (Applications), people the next person of the voice chat (People), auto either, devices the next device without a channel (Devices), and - a dark strip (Channels).

Applying changes¶

The daemon takes a saved file by itself, a moment after the file stopped changing: no restart, slots whose strip stays the same keep it. A file with errors is reported in the log and the current configuration stays. To check a file first, or to load it again by hand:

xtouch-daemon check-config && systemctl --user reload xtouch-daemon

A reload (SIGHUP) does the same as a change of the file.

Two sections need a restart (systemctl --user restart xtouch-daemon):

  • A changed [device] name or virtual. A reload takes the rest of the file, but keeps the old device.
  • A changed [mqtt] section. Until the restart, a reload keeps the whole current configuration.

The GUI applies a saved file the same way, at once: it reloads the running daemon (the service, or one started from a terminal or an IDE), or offers a restart. It then tells whether the daemon took the file.

Complete example¶

[behavior]
max_volume = 130
encoder_step = 2

[aliases]
"WEBRTC VoiceEngine" = "Discord"

[channel.out]
type = "output"
device = "alsa_output.pci-0000_11_00.4.analog-stereo"
label = "Speaker"
color = "cyan"

[channel.buds]
type = "output"
device = "bluez_output.4C_D7_3A_EA_02_76.1"
label = "Buds"
color = "green"

[channel.mic]
type = "input"
label = "Mic"
color = "red"

[channel.browser]
type = "apps"
match = ["@browsers"]
label = "Browser"
color = "yellow"

[channel.game]
type = "apps"
match = ["@games"]
label = "Game"
color = "magenta"

[pool.apps]
exclude = ["speech-dispatcher", "notification"]

[state.gaming]
mode = true
label = "Gaming"
processes = ["@steam-games"]

[slots]
1 = "out"
2 = ["buds if present", "-"]
3 = "mic"
4 = "browser"
5 = ["game if gaming", "-"]
# slots 6 to 8 have no entry: they are "auto"
